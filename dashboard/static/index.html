HELP step-by-step guide for every tab

ASCII English only. Button and tab names match the UI above. Only check websites you own or have written permission to test.

1. Sign in

  1. On first start, the gate asks you to choose a password (12+ characters) and confirm it. Nothing in .env is required.
  2. Later visits: type that password and press SIGN IN.
  3. The badge must say online. After 15 minutes with no click, LOCK happens automatically -- sign in again.
  4. Press LOCK (top right) to sign out now.

Other tabs do not load data until sign-in succeeds. There is no global SITE in the header; each tab has its own picker.

What this platform does

You give it a domain you own. It looks from the outside (like a visitor, no login):

  1. Finds names under that domain (for example api.example.com).
  2. Checks which names are alive and which IPs they resolve to.
  3. Reports open ports on those servers.
  4. Compares with the previous check and marks what is new.
  5. Optionally sends Telegram and builds HTML / PDF / CSV / JSON reports.

2. First run (zero to report)

  1. Sign in (section 1).
  2. SETTINGS: enter your Telegram username or numeric id, press SAVE SETTINGS, then SEND TEST NOTIFICATION. If you use a personal username, open the bot in Telegram and press Start once first. Same page: PORT SCAN chooses full / top ports / custom (see 3b).
  3. TARGETS: type the domain on the left (for example example.com), ADD / LOAD, then SAVE PROFILE.
  4. TOOLS: leave ENABLED the scanners you want. The change applies on the next check. Same binary can appear on more than one row -- use SWITCH to see which control you are toggling.
  5. WORDLISTS: tick lists per step and press SAVE SELECTION. For a short test keep the smoke list. Million-line lists take much longer.
  6. SCAN: ADD TARGET (or ADD LIST), optionally SETUP, then START on that site's row. Authorize adds missing names to scope.
  7. Expand a site on SCAN and watch that site's live log until the run finishes.
  8. RESULTS: pick the site, press LOAD RESULTS.
  9. REPORTS: pick the site, press GENERATE NOW, then OPEN next to report.html or the PDF.

3. SCAN -- every site, expandable

This tab lists every registered website. Each site has its own workspace. ADD LIST plus START on each row is how you check several domains.

  1. Type a domain in SITE.
  2. ADD TARGET registers one domain (isolated folder + profile) without starting a check.
  3. ADD LIST registers many domains at once (one per line, or comma-separated).
  4. Authorize this target -- adds each new domain to scope.yaml if missing.
  5. On that site's row, press START to begin a check when the site is idle. Add the site first. START does not kill a live scan.
  6. SETUP is optional. If you skip it, this site uses global SETTINGS / TOOLS / WORDLISTS. Uncheck inherit to pick tools (each row says what it does) and tick wordlist filenames on this same page. SHOW NAMES previews entries in a file. Automatic checks for this site are also in SETUP.
  7. START / RESUME / RESTART / STOP / DELETE on a row apply only to that site. START begins a new ladder when idle. RESUME continues done modules. RESTART stops a live scan for this site, then starts from the first module. The dashboard clears circuit-breaker pauses automatically when a run starts or the next module is due — you do not click a limiter button. DELETE hides it from SCAN immediately; warehouse records stay for 7 days, then that site's files are removed.
  8. Each SCAN row shows live dnsx parent / hit count / QPS, and warnings from the last run (false QPS collapse, canary latency, tool timeout, paused breaker). A breaker pause is cleared automatically when the next module (or the next START / RESUME) runs.

SCHEDULER

Global defaults live in SETTINGS (automatic checks on/off and interval, minimum 10 minutes). Each site can enable, change the interval, or turn checks off in SETUP / TARGETS. Empty per-site fields inherit SETTINGS. Example: 720 minutes is about twice a day.

LIVE LOG and AGENT JOURNAL

LIVE LOG is the diary of the site in the SITE box (and the last row you expanded), streaming live. Use Readable for a human summary (time, step, what happened) or Raw for the exact file. AGENT JOURNAL fills only if the optional assistant is on in SETTINGS. Normal use does not need it.

3b. Port scan -- pick coverage like nmap -p

After names are merged, each unique IP is port-scanned. You choose the coverage the same way you would pass -p to nmap. Set the default in SETTINGS -> PORT SCAN, or override one site in SCAN SETUP / TARGETS. Press SAVE SETTINGS or SAVE SETUP. The next START uses the new mode.

  1. full -- every TCP port 1-65535 (like nmap -p-). Slowest, most complete. Default.
  2. top ports -- the most common TCP ports (naabu top 100, like nmap --top-ports 100). Fast preview of typical services.
  3. custom -- only the ports you type, same syntax as nmap: 22,80,443,8000-8080. You may paste -p 22,80,443 or T:443. Custom mode needs a non-empty list.

SERVICE VERSION (default on) runs nmap -Pn -sV on the open ports that the sweep found. -Pn skips ping/host discovery so a host that ignores ICMP is still fingerprinted instead of hanging or being marked down. RESULTS then shows product and version when you click an open-port count, then an IP.

An early optional port-check row in TOOLS is only a fast top-ports peek while DNS is still running. The mode you pick here is the main post-MERGE sweep.

4. TOOLS -- enable or disable scanners

The same binary can appear twice (ffuf, dnsx, naabu, httpx) because each row is a different technique. Columns:

  1. BINARY -- original tool name. Duplicates here are expected.
  2. SWITCH -- unique id this ENABLED button writes (for example ffuf vs ffuf-vhost).
  3. TECHNIQUE -- how that row inspects the site.
  4. THIS SWITCH CONTROLS -- exactly what you turn on or off for the next scan.
  5. BRANCH -- active or passive lane.
  6. ENABLED -- applies on the next check, not the run already in progress. Internal echo/fallback tools stay hidden.

Empty table: sign in first. HTTP 401 means the session expired -- press SIGN IN again.

naabu appears three times. naabu is the optional early peek. naabu-full and naabu-sweep are engines for PORT SCAN MODE full vs custom. Pick full / top ports / custom in SETTINGS or SETUP -- not by turning those rows off. LOCKED ON on naabu-full only means the full-mode engine stays available.

5. WORDLISTS -- original filenames

Three separate steps. Filenames stay as in SecLists (for example subdomains-top1million-5000.txt), not internal YAML keys.

  1. DNS brute (dnsx) -- name guesses resolved to IPs (DNSR-1). This is the active subdomain finder.
  2. HTTP length + tech (httpx) -- when ENABLED, each resolved name is probed so RESULTS shows response length and technology.
  3. Virtual hosts (ffuf) -- Host-header virtual hosts on those IPs (FFUF-2).

For each table:

  1. Tick the lists you want.
  2. Optional: filter by filename, or SELECT-ALL (visible).
  3. Always SAVE SELECTION -- ticks do nothing until saved.

Bigger lists find more names and take longer. Keep the short list for a smoke test.

6. TARGETS -- per-site profile

The platform is multi-target. Empty fields inherit SETTINGS. The same profile is also editable from SCAN -- expand a site and press SETUP / SAVE SETUP.

  1. Type the domain on the left, press ADD / LOAD.
  2. Fill the cards on the right, press SAVE PROFILE.
  3. EDIT in the table loads that site. DELETE PROFILE removes the profile (recon data on disk is not necessarily deleted).

Fields

  • DESCRIPTION -- short ASCII note.
  • TELEGRAM USERNAME OR ID -- jackjohns, @jackjohns, or a number. Empty = global SETTINGS.
  • TELEGRAM NOTIFICATIONS -- on, or MUTED for this site only.
  • WATCHTOWER INSTANT ALERTS -- instant change alerts, or off.
  • DIGEST THRESHOLD -- above this many new findings, one summary message instead of a flood.
  • PROXY POOL -- proxies for this site only; empty = global pool.
  • Budgets -- time/depth caps. Empty = defaults. Nested DNS / vhost depths are independent.
  • PORT SCAN -- full, top ports, or custom nmap -p list for this site. Empty = SETTINGS. Service version is nmap -Pn -sV.
  • MODULES -- leave empty for defaults. Advanced operators only.
  • WORDLIST OVERRIDE -- per-site lists, otherwise the WORDLISTS tab.
  • SCHEDULER -- automatic checks for this site: inherit, on, or off, plus an optional interval (min 10). Empty = SETTINGS.

7. RESULTS -- read findings

Choose a site that you added on SCAN. The list is that board, not a default leftover.

  1. Pick the site. While a scan is running, this page auto-refreshes LIVE RESULTS from dnsx output (you do not wait for MERGE). Press LOAD RESULTS anytime.
  2. Filters match the table columns: host, open ports (has / none), alive, length, tech, source, tag, first seen, last seen, plus free text, IP search, and scope.
  3. APPLY runs the filter. COPY URL copies a restore link. CLEAR resets filters.

Asset table

  • HOST -- discovered name. Click a live host to open it in a new tab.
  • OPEN PORTS -- how many ports are open on this name. Click the count to see each IP, then click an IP for port / product / version.
  • ALIVE -- answered or not.
  • SOURCES -- which source found it (overlap is normal).
  • TAGS -- labels such as dev.
  • JSON -- raw record.
  • FIRST / LAST SEEN -- first and last check that recorded this name (this site only).

Each site has its own warehouse file under recon/<site>/warehouse.sqlite. Records from one site never mix with another. Use FROM RUN / TO RUN then COMPARE RUNS to see what changed between any two checks, not only the latest pair. Diff badges such as +3 hosts mean three new names in that window. SOURCE COVERAGE shows how unique each source is.

8. REPORTS -- shareable output

  1. Pick the site from the SCAN list.
  2. CHECK BUNDLE lists files that already exist.
  3. GENERATE NOW builds a fresh pack: HTML, PDF, CSV, JSON, Markdown.
  4. Press OPEN. Each file has SHA256 so you can prove it was not modified.

9. API KEYS -- optional

The platform works with zero keys. Some public sources go deeper with a free key. Without a key that source is skipped openly.

  1. Each row: key name, module, and behavior without the key.
  2. Paste, press SAVE -- takes effect on the next check; the value is masked after save.
  3. DEL removes it from .env.

10. SETTINGS -- global defaults

Press SAVE SETTINGS after every change. Empty TARGETS fields inherit from here.

Scheduler

AUTOMATIC CHECKS and INTERVAL (min) are the default for every site (minimum 10). A site SETUP can turn checks on, change the interval, or disable them for that site only. Press SAVE SETTINGS after changing the global defaults.

Recon depth

NESTED DNS, NESTED VHOST, and PASSIVE RECURSION depths are independent (1-5 / 0-5). A site SETUP can override each one.

Port scan

Choose full (all TCP ports, like nmap -p-), top ports (common ports), or custom and type an nmap -p list such as 22,80,443,8000-8080. Service version uses nmap -Pn -sV so firewalled hosts still get product/version. See 3b. Port scan.

Network

  1. PROXY URL -- one proxy for every check. If it is unreachable, the check refuses to start (it does not silently go direct).
  2. PROXY POOL -- comma-separated proxies, used in turn. Health-checked before a run; the assignment is in the run log.

Telegram

  1. Set only your username or id. The bot token usually lives in .env; leave the token box empty unless you need an advanced override.
  2. Press SEND TEST NOTIFICATION. If nothing arrives: Start the bot in Telegram, or check the installer token.
  3. DIGEST THRESHOLD -- when to collapse many findings into one message.

Telegram change alerts

Tick each asset type and whether New / Removed / Changed should notify Telegram. Unticked kinds still show in RESULTS diffs. Host CHANGED includes HTTP response length. Optional: alert new hosts only when the server IP is also new.

Supervisor agent (optional)

Default off. If on, it can suggest or auto-fix common failures. MAX LLM CALLS is the per-run cap. The platform is complete without it.

Log retention and resources

Old snapshots compress/prune so the disk is not filled; result data and reports are not deleted. CPU CORES and RAM MB cap this machine. Save again after filling them.

Safety

  1. Only your assets, or written permission.
  2. Out-of-scope domains are refused -- that protects you.
  3. The check looks from the outside; it does not fill forms or write to the site.

11. If something fails

  • offline -- the dashboard process is not up.
  • session expired or empty tables -- SIGN IN again.
  • Start refused -- tick Authorize, or register the site in TARGETS first.
  • Port scan stuck or hosts look down -- SERVICE VERSION already uses nmap -Pn. If custom mode was selected with an empty list, the sweep is skipped; pick full / top ports or fill CUSTOM PORTS.
  • No Telegram -- Start the bot; a public channel needs the bot as a member.
  • TOOLS / WORDLISTS empty after SET -- click the tab again and read any error row.
